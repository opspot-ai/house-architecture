# Capability-owned example

Consider a commerce application with account, catalog, and checkout capabilities. A capability owner maintains the checkout module, its contract, and focused fixtures. Shared specialists own authentication, storage, and the integration path; checkout requests changes to those shared seams through their owners.

A validated registry checks capability declarations without launching work or mutating user state. A shared board records ownership and prerequisites. Integration verifies one representative purchase journey across the modules before the application relies on additional capabilities.

This example illustrates ownership and integration principles only. It defines no implementation schema, team size, runtime, or product requirement.
